# Phygital Pass — порядок развития продукта

Принцип: новый экран или упражнение добавляется только после того, как предыдущая стадия демонстрируется без ручных объяснений и с понятными данными. «Вау» не должен подменять измерение.

## Стадия 0 — доверие к измерению

**Цель:** эксперт и пользователь понимают, почему попытка засчитана или отклонена.

- Показывать засчитанные и отклонённые попытки, а также причину: недостаточная глубина, слишком быстрый темп или потеря трекинга.
- В итоговом паспорте показывать `засчитано / попытки`, а не выдавать цель теста за число всех движений.
- Калибровать пороги на нескольких людях, с разным освещением и положением камеры.
- Сохранить отказ от медицинских выводов.

**Готовность:** десять проверок на реальной камере, где ручная запись попыток совпадает с результатом приложения или расхождение объяснимо.

## Стадия 1 — убедительный личный паспорт — реализовано

**Цель:** показать не разовый счётчик, а понятную ценность для студента.

- Хранить историю локальных тестов: дата, результат, темп, глубина, доля засчитанных попыток. ✓
- Добавить экран прогресса: лучший результат, последняя попытка, изменение за неделю. ✓
- Дать возможность поделиться результатом как изображением-карточкой без видео. ✓

**Готовность:** один человек может пройти тест дважды и увидеть измеримое изменение, не создавая аккаунт.

## Стадия 2 — полноценный двигательный профиль — отложено

**Цель:** сделать слово «паспорт» содержательным.

- Второй тест не добавляется в этой итерации.
- До появления отдельно калиброванного упражнения продукт показывает один измеримый показатель и не делает медицинских выводов.

**Готовность:** каждый тест имеет собственные правила засчитывания, подсказки и unit-тесты последовательностей движений.

## Стадия 3 — челленджи и университетский пилот — реализовано технически

**Цель:** дать преподавателю и спортивному клубу причину использовать продукт регулярно.

- Недельный челлендж с прозрачными правилами и дедлайном. ✓
- Серверное хранение псевдонимизированных результатов и команд. ✓
- Лидерборд показывает только проверенные организатором результаты; согласие и удаление данных включены в процесс. ✓

**Готовность:** пилот на 10–20 студентах с заранее измеримыми KPI: завершение теста, повторное участие, совпадение с ручной проверкой.

## Стадия 4 — кабинет организатора — реализовано технически

**Цель:** управлять пилотом без ручного сбора скриншотов.

- Создание челленджа, просмотр агрегированных результатов, экспорт обезличенной статистики. ✓
- Роли преподавателя и участника, политика хранения данных, удаление результатов по запросу. ✓
- Настройка порогов упражнений только через версионируемые конфигурации. ✓

## Стадия 5 — поздние улучшения

Эти функции не должны задерживать пилот: аватары, достижения, социальная лента, генеративные советы, интеграции с носимыми устройствами, VR/AR и анализ матчей.

## Что сделать перед первым пилотом

1. Закрыть Стадию 0: проверить обновлённый счётчик на реальной камере и подстроить пороги только по наблюдаемым ошибкам.
2. Подготовить домен и VPS по инструкции из README, выполнить резервную копию базы.
3. Провести закрытый пилот на 10–20 студентах и сверить ручную проверку с результатами приложения.
4. Не добавлять второе упражнение, пока эти три пункта не проходят стабильно.
